## DND - Rules-as-code pipeline (Quint spec → TypeScript runtime → MCP)

**Headline / public validation:**
- "Model-Based Testing for Dungeons & Dragons" reached the Hacker News
  front page (109 points, 76 comments).
- Companion piece: "Formally Specifying Dungeons & Dragons Rulebooks."
- Substrate is a tabletop rulebook; the technique generalizes directly
  to any rules-heavy domain — pricing, permissions, claims, workflow
  engines, regulatory state machines.

**The engineering problem:**
Treat a written rulebook as a specification. Lift the rules into Quint
(TLA+-derived formal modeling language), model-check with Apalache,
then enforce that the production TypeScript runtime refines the spec by
replaying Quint-generated traces against it (`quint-connect`).
Surface the runtime through both an MCP server (for AI agents) and a
React app (for humans).

**Resume-relevant signal:**
- Formal methods in real production TypeScript — not academic toy code.
  Spec / runtime conformance is enforced mechanically, not by review.
- Large TypeScript monorepo (~7 packages, pnpm + Turbo) with strict
  package-boundary discipline and custom CI coverage tooling (rules-
  kernel coverage, dispatch-boundary checks, unit-profile coverage).
- XState UI logic driven by the same spec the backend tests against —
  one source of truth across UI, backend, and MCP surface.
- MCP server exposing the runtime to LLM agents — same toolchain as the
  Huly MCP work but applied to a fully owned domain model.
- Public technical writing strong enough to hit HN front page.

**Stack:** TypeScript, Quint (+ Apalache), XState, MCP SDK, React, pnpm
workspaces, Turbo.

## HEADLESS-CHAT - Discord-Grade Real-Time Chat Library
Location: /Users/firfi/work/typescript/headless-chat
Last modified: 2025-09-22

**What it is:**
- TypeScript-first, framework-agnostic real-time chat library
- Positioned as Discord/Slack-grade alternative to @yext/chat-headless
- Turborepo monorepo: @headless-chat/types, /core, /react

**Technical achievements:**

1. **Cursor-Based Message Reconciliation**:
   - Dirty/clean message separation model
   - clearMessages: guaranteed-ordered messages from server
   - dirtyMessages: locally queued/unconfirmed during sync
   - Cursor system enables partial range queries (no full resync)

2. **Composite Message IDs** - Distributed ordering:
   - Format: {timestamp}-{counter}
   - Guarantees ordering even with out-of-order delivery
   - Prevents collisions in distributed systems
   - Enables conflict resolution without coordination

3. **Multi-Room Architecture**:
   - rooms: ImmutableMap<ChatRoomId, RoomState>
   - Not limited to single conversation (unlike competitors)
   - Scales to 1000s of concurrent rooms
   - Presence tracking via users: ImmutableSet<UserId>

4. **Gap Detection & Recovery**:
   - Reconciliation algorithm (lines 101-184 in core.ts)
   - Detects gaps between local and remote messages
   - Only syncs missing range (not full resync)
   - Handles islands of messages with gaps (warns, doesn't crash)

5. **WebSocket-First Protocol**:
   - 3-second heartbeat (ping/pong) for connection health
   - Automatic reconnection with 3-second delay
   - TCP + persistent connection (vs HTTP polling)

**Architecture patterns:**

1. **Functional Programming with Immutable.js**:
   - Pure reducer pattern (no mutations)
   - Deterministic state transitions
   - Structural sharing prevents memory bloat
   - Time-travel debugging/replay

2. **Type-Safe Runtime Validation (io-ts)**:
   - Codec-based validation at boundaries
   - Type erasure checked at runtime
   - Single source of truth for types

3. **Pattern Matching (ts-pattern)**:
   - Exhaustive handling of all action types
   - More readable than switch/case

**Tech stack:**
- fp-ts, immutable, io-ts, ts-pattern, React, WebSocket

**COMPARISON.md highlights:**
- ✅ WebSocket-first (vs HTTP/SSE)
- ✅ Multi-room support (vs single conversation)
- ✅ Cursor-based synchronization
- ✅ Composite message IDs for ordering
- ✅ Gap recovery without full resync

**Resume angle:**
Distributed systems, cursor-based reconciliation, functional patterns, real-time protocols
